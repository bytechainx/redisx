# redisx 标准

**crate**：`redisx` v0.1.0 · 依赖：`redis` 0.27、`tokio`、`thiserror`、`serde`、`serde_json`、`toml`、`tracing`、`url`、`bytes`、`futures-core`、`futures-util`

## 1. 定位

redisx 提供生产可用的异步 Redis 适配器：单一 crate 内覆盖 Standalone / Cluster / Sentinel 三种拓扑、连接池背压、会话级超时/重试、核心数据结构与 Streams 原语。零内部耦合，不依赖任何私有基础设施 crate；不实现缓存语义层或 Redis 服务端。

## 2. 配置治理

- `RedisConfig`：结构体 + `builder()` / `from_env()` / `from_toml()` / `from_url()` + `validate()`，校验失败 fail-fast。
- 环境变量键见 `config` 模块 `ENV_*` 常量（addr、mode、db、tls、password、max_in_flight、blocking_timeout 等）。
- Sentinel 模式必须提供 `sentinel_master`；Cluster 不支持非 0 逻辑库——两者都在 `validate()` 拦截。
- 密码/Token 只能经 env 或 builder（含 `password_from_provider`）注入；`from_toml()` 拒绝明文密码；`Debug` 与 `display_endpoint()` 一律脱敏。

## 3. 连接与背压

- 连接池以 `max_in_flight` 许可 + `acquire_timeout` 构成有界背压，禁止无界排队。
- 所有外部调用具备超时：`connect_timeout` / `command_timeout` / `acquire_timeout` / `blocking_timeout` 均可配置。
- `close(timeout)` 优雅排空在途命令；`health_check` / `stats` / `metrics_snapshot` 提供结构化可观测数据。

## 4. 重试与副作用安全

- 命令必须先归类 `RedisOperation`，经 `retry_safety()` 得到 `ReadOnly` / `Idempotent` / `AmbiguousWrite` / `NeverAutomatic`。
- `with_retry` 只对只读与幂等命令自动重试；结果不明或非幂等命令永远只执行一次。
- 退避为指数增长，可叠加抖动与总 deadline（`RetryConfig`）。
- `RedisError::is_retryable()` 区分瞬时故障与业务拒绝。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

测试至少覆盖：配置构建/校验与 env 解析（`tests/config_and_env.rs`）、纯函数行为与重试安全分类（`tests/pure_behavior.rs`）、公开 API 面（`tests/public_api.rs`）、不可达地址的连接失败路径（`tests/unreachable_connect.rs`）。全部离线，不依赖真实 Redis 服务。

基准：`benches/hot_path.rs`（`harness = false`，离线）覆盖配置构建 → validate → 端点脱敏展示 → 重试安全分类路径；`cargo bench --bench hot_path -- --quick` 用于快速冒烟（`cargo test` 以 `--test` 模式运行时自动缩减为 10 次迭代）。
